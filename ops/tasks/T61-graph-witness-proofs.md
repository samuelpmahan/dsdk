# T61-graph-witness-proofs

**Goal.** Make the graph layer stand on the logic layer: implement `node_var`, `known_premises`, `_missing`, `witness_proof`, `unreachability_countermodel` and `entailed_by_known_edges` in the new module `src/dsdk/graph/proofs.py`. A graph is read as a set of implications; a reachability witness becomes a modus-ponens proof that `dsdk.logic.check` accepts, and non-reachability becomes a countermodel that `dsdk.logic.evaluate`, `entails` and `countermodel` confirm.

**Pitfalls.**
- Variables are index based: `node_var(g, node)` is `Var(f"n{g.index_of(node)}")`. Do NOT build the name from `str(node)` (different nodes can print the same, and a node can be a core Part). `g.index_of` raises `MissingNodeError` for an absent node by itself. `TypeError` first for a non-`Graph`.
- `known_premises(g)`: loop over `g.edges` in order; skip every edge whose `evidence` is not `Status.KNOWN` (uncertain edges are NEVER premises); append `Implies(node_var(g, e.source), node_var(g, e.target))`; for an UNDIRECTED graph also append the reverse implication, except when source equals target (a self-loop gives one premise). Return a tuple.
- `_missing(g, source, target)`: for each of `source`, `target` in that order, if `not g.has_node(node)` return `Judgment(Status.INVALID, None, f"node {node!r} is not in the graph")`; else `None`. Use it first (after the `TypeError` check) in the three public functions.
- `witness_proof`: take the verdict `reachable(g, source, target)`. If its status is `UNKNOWN`, return that verdict UNCHANGED (no proof). If it is KNOWN with value False, return `Judgment(Status.NOT_APPLICABLE, None, f"no proof exists: {target!r} is not reachable from {source!r}; ask for the countermodel instead")`. Otherwise the path is `shortest_path(known_subgraph(g), source, target)`. Build the steps exactly as the docstring shows: step 0 is `Step(node_var(path[0]), Rule.PREMISE, ())`; for each `i` from 1 to the last index of the path add the premise step `Step(Implies(var(path[i-1]), var(path[i])), Rule.PREMISE, ())` and then `Step(var(path[i]), Rule.MODUS_PONENS, (2*i - 1, 2*i - 2))` (implication cited FIRST). Premises tuple is `(node_var(g, source),) + known_premises(g)`. Run `check(steps, premises)`; if `not result.ok` return `INVALID` with a reason starting `"proof failed its own check: "` plus `result.reason`. Return `Judgment(Status.KNOWN, GraphProof(tuple(path), premises, tuple(steps)), "")`.
- `unreachability_countermodel`: `known = known_subgraph(g)`; `reached = set(bfs(known, source).distance)`. If `target in reached` return `NOT_APPLICABLE` with a reason starting `"no countermodel exists:"`. The assignment is `{f"n{i}": node in reached for i, node in enumerate(g.nodes)}` (a variable for EVERY node). Check it: every premise true under `dsdk.logic.evaluate(premise, assignment)` and the target variable false, else `INVALID` starting `"countermodel failed its own check:"`. When `len(g.nodes) <= MAX_ENUM_NODES` also compute `logic_cm = countermodel(premises, goal)` and require `entails(premises, goal)` to be False and `logic_cm` not None (else `INVALID` starting `"logic disagrees:"`); set `cross_checked=True`; otherwise `logic_cm=None` and `cross_checked=False`. `unreachable` is True exactly when `reachable(g, source, target)` has status KNOWN and value False. `reached` in the result is the tuple of reached nodes in `g.nodes` order.
- `entailed_by_known_edges`: more than `MAX_ENUM_NODES` nodes -> `Judgment(Status.UNKNOWN, None, f"too many nodes to enumerate: {len(g.nodes)} > {MAX_ENUM_NODES}")`; otherwise `Judgment(Status.KNOWN, entails((node_var(g, source),) + known_premises(g), node_var(g, target)), "")`.
- The Python names `countermodel` (the function from `dsdk.logic`) and `Countermodel` (the dataclass in this file) are different things; do not shadow either.
- The 2000-node path test needs no recursion: use only the library functions named above.
