# Make graph witness paths into checked logic proofs
kind: cross-track link
idea: Treat a directed graph as a set of implications: an arrow a to b is the formula "a implies b", and "t is reachable from s" is the claim that the formulas plus "s" entail "t". A shortest-path witness is then a proof by repeated modus ponens, one step per arrow. The graph package would build that proof as a dsdk.logic Proof (one Step per arrow) and call the logic package's proof checker on it, and a "not reachable" answer would come with a countermodel from logic.countermodel (the set of nodes reached is a model of the formulas in which t is false).
why it's interesting: Today the graph layer calls only two kernel helpers, so it stands beside the layers below it rather than on them. This makes the claim "here is why you can get from track X to track Y" a checkable object instead of a list, which is exactly what the "How do we know?" drawer in the Lab wants to show for the six-degrees instrument on Sam's Lost Lands data. It also gives a second, independent implementation of reachability (a logic one) to cross-check the breadth-first one.
smallest experiment: Add one function to the graph package, witness_proof(g, source, target), that returns a logic Proof for a reachable pair, and a function that returns the countermodel for an unreachable pair. Test: for every directed graph on up to 4 nodes, logic.check accepts the built proof, the proof has exactly distance-many inference steps, and the countermodel makes every arrow formula true and the target false.
reuses: dsdk.graph bfs and shortest_path (the witness), dsdk.logic Proof, Step, check, entails and countermodel, dsdk.core Judgment (reachable already returns it).
probe: Read-only, on the real code. For every directed graph with 2, 3 and (a sample of) 4 nodes, self-loops included, and every source, I asked dsdk.logic.entails whether "source plus every arrow as an implication" entails each node, and compared it with the set that dsdk.graph.bfs reaches. 154,480 (graph, source, target) triples, 0 disagreements. Command: entails([Var(source)] + [Implies(Var(a), Var(b)) for each arrow], Var(target)) against set(bfs(g, source).distance).
score: surprise=3 cost=2 reuse=5
