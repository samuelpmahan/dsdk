# Store a logic proof as kernel Parts so its lineage graph is the proof
kind: instrument
idea: Record a proof (from the logic package, or the witness proof the graph package now builds) in a PxC store with one Part per step: a premise step is a raw Part, and every modus-ponens step is a composed Part whose inputs are exactly the Parts it cites, produced by a calculation that applies the rule. Then dsdk.graph.lineage_graph of the last step IS the proof's dependency graph, and checking the proof means re-running the compositions.
why it's interesting: Today the logic package calls exactly one kernel function, so it stands beside the kernel instead of on it. This turns the "How do we know?" drawer into a real picture of a derivation (for example why one Lost Lands track can reach another), and it ties three layers together: logic proofs, kernel lineage, graph traversal.
smallest experiment: A function that takes a list of Steps and a store and returns the last step's Part; tests that the lineage graph has one node per step plus the calculation Parts, that its edges are exactly the citations, that a tampered step makes the composition fail with a FAILED receipt (the tick rolls the whole proof back), and that logic.check accepts exactly the proofs whose recording succeeds.
reuses: dsdk.logic Step, Rule, check; dsdk.core PxC.compose, tick and receipts; dsdk.graph lineage_graph, topological_order and witness_proof.
probe: Read-only, on the reference witness_proof: for the chain a to b to c to d the proof has 7 steps and 6 citation edges; as a graph over step indices the citation edges contain no cycle and the topological order is exactly 0 to 6, so a proof is already the kind of DAG the kernel's lineage graph represents. Command: Graph.from_edges over (cited index, step index) pairs, then find_cycle and topological_order.
score: surprise=3 cost=3 reuse=5
