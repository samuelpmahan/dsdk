    How do we know?

    The page runs the same JavaScript logic engine that is held to the Python-verified fixtures. Pit facts and Wumpus facts share no variables, so each square is two separate entailment checks: the knowledge base must prove "no pit here" and "no Wumpus here". The agent is sound but deliberately incomplete. It does not assume exactly one Wumpus, and it never gambles. When nothing is provable it climbs out. That is where the probability rung takes over: dsdk.prob answers the exact chance of a pit or the Wumpus on each frontier square, and the optional probabilistic agent steps on the least risky one. dsdk computes those numbers when the page is built; this page recomputes every one itself and shows agree or DISAGREE.

    How do we know?

    Every number comes from ops/ledger.jsonl, which is appended after the planner re-runs each claimed result. The first-try rates and the per-round bars are computed by dsdk itself: dsdk.worlds.first_try_summary reads the ledger and calls dsdk.prob.exact_interval, an exact (Clopper-Pearson) 95% interval whose coverage is at least 95% for every sample size. This page recomputes each interval in its own JavaScript and shows "page recomputes: agree" or "DISAGREE" under each tile. An earlier version showed Wilson intervals; the probability-proof audit found those really cover only about 84% of the time near 0% or 100%, which is where Haiku's rate sits.
